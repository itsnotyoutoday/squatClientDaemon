# PROTOCOL.md ambiguities and the choices made in pkg/ansi, telnet, conn, scrollback

1. **TLS handshake failure reason.** 6.5 lists `connect_failed` as "DNS/TCP/TLS failure before the connection was established" but also defines `tls_error`. Choice: failures during the TLS handshake (bad certificate, pin mismatch, non-TLS peer, handshake timeout) -> `tls_error`; DNS/TCP failures -> `connect_failed`; TLS errors on an established connection -> `tls_error`. Suggest clarifying 6.5.
2. **Corrupt MCCP2 stream.** No end reason fits. Choice: `remote_closed` with `endDetail` starting `mccp2:`.
3. **MTTS UTF-8 bit.** 6.1 says "if encoding utf-8"; `proto.Caps.UTF8` exists too. Choice: bit follows the world encoding only; `Caps.UTF8` is not consulted. A zero-value `Caps{}` in `conn.Config` is replaced by `proto.DefaultCaps()` (so "everything off" cannot be expressed).
4. **TTYPE and `SetCaps`.** The cycle is 3 steps and repeats the last. After a caps change the next SEND is answered with the new `MTTS n` (not restarted from `SquatClient`).
5. **CHARSET for latin1 worlds.** Spec: reject unless utf-8 offered and world is utf-8. Implemented as written (REJECTED for latin1 worlds even if ISO-8859-1 is offered).
6. **Telnet `DO ECHO`/`DO GMCP` from the server** (server asking *us* to echo / enable GMCP on our side) are refused with WONT. SGA is accepted in both directions.
7. **"Lines longer than 65 536 chars".** Implemented as 65 536 decoded UTF-8 *bytes*, cut on a rune boundary and not inside an escape sequence.
8. **Prompt flush with only escape sequences.** A flushed partial line that yields no spans (e.g. just `ESC[0m`) updates ANSI state but emits no `prompt` line. A trailing *incomplete* escape sequence is held back and not flushed.
9. **OSC 8 link state persists across lines** like colours (6.3 only says "style state"). `Parser.Reset` clears it; SGR 0 does not.
10. **`send` with trailing newline.** 4 says "no trailing newline"; the engine splits strictly on `\n`, so `"a\n"` sends `a` and an empty line. `\r\n` is normalised to `\n`, lone `\r` removed.
11. **`firstSeq` with the on-disk log.** 5 defines it as "oldest seq still retained" and says the ring is a cache of the log. Choice: with a LogDir `firstSeq` is the oldest entry on disk; memory-only stores report the ring start. If `since` is *ahead* of `lastSeq` (e.g. a client with a stale state after a daemon log reset) the last `maxBacklog` entries are replayed with `gap=null`.
12. **Gap when within range but beyond maxBacklog.** If `since` is retained but more than `maxBacklog` entries behind, only the last `maxBacklog` are replayed and `gap.missed` reports the skipped ones (5.1 allows capping; the gap is added so clients can show it).
13. **`lastText`** is the last line whose plain text is non-blank, including flushed prompts.
14. **NAWS default** is 80x24 until `Resize` is called (spec silent).
15. **Subnegotiation hardening.** `IAC SB ... IAC <x>` where `<x>` is neither `SE` nor `IAC` abandons the subnegotiation; subnegotiations over 1 MiB are discarded; `SB MCCP2` without a prior `WILL MCCP2`/`DO MCCP2` handshake is ignored.

# squatterd / pkg/wire / pkg/auth: choices and deviations (daemon implementation)

16. **Replay seam implemented without a separate buffer.** 5.1 says live entries produced during replay are buffered per client and flushed after `done:true`. The daemon takes the replay snapshot, enqueues `attached`, `backlog*` (done) and registers the client in ONE critical section of the session lock; live entries are produced under the same lock, so the client's ordered queue is exactly `attached, backlog..., done, live...` with no duplicate and no gap. Observable behaviour is identical to the spec; tested with a raw (non-deduplicating) client.
17. **Echo while the game has `WILL ECHO` (password prompt) is masked.** A `send` normally yields an echo line with the typed text (kind `echo`). While `remoteEcho` is true the echo line contains `********` instead, so game passwords never reach the scrollback, the disk log or other clients. (The text is still sent to the game unchanged.)
18. **`send` with embedded `\n` produces one echo line per line** (same split rule as `conn.Send`; see note 10). An empty line echoes as `spans: []`.
19. **Replies for requests without a dedicated reply.** `session.disconnect` is answered by the `session.state` broadcast (ended/`client_quit`); `session.dismiss` by the `session.removed` broadcast to ALL clients (no `reqId`). Errors always carry `reqId` when the request had an `id`. Dismissing a live session returns `bad_request` ("disconnect it first"); disconnect/send on an ended session returns `session_ended`; `resize` on an ended session is silently ignored.
20. **`session.created` and state broadcast.** The creator receives `session.created` (with `reqId`) and, like every client, the `session.state` broadcasts (so it may see a `connecting` state before the `created` reply).
21. **`unread`** is `lastSeq - ack` where ack is the device's last acknowledged seq (0 for a device that never acked: everything is unread). `ack` beyond `lastSeq` is clamped. Acks are persisted in `meta.json` by a 2 s flusher (a crash can lose the last 2 s of acks).
22. **Limits.** Frames: 1 MiB after auth, 16 KiB before auth. 20 consecutive malformed frames, any binary frame or an oversize frame close the connection. Unauthenticated clients that send anything but a valid `hello` get `auth_failed` and are closed. More than `--max-clients` authenticated clients or `--max-sessions` sessions (ended ones count): new client gets `rate_limited` + close; new session gets `bad_request`. `send.text` is capped at 64 KiB. `attach.maxBacklog` is clamped to 1..20000.
23. **Liveness.** The daemon's `ping` is an application-level JSON frame every 20 s; ANY inbound frame (pong, request) counts as liveness. A client silent for > 60 s is dropped (checked every 15 s, so the worst case is about 75 s). A client is also dropped when its outbound queue exceeds 1000 frames or one write blocks for 10 s.
24. **Revocation** (`squatterd revoke`) takes effect at the next `hello`; an already connected client stays connected until it disconnects.
25. **Dismiss deletes** `sessions/<id>/` (meta + log); there is no archive.
26. **Caps.** A session starts with the creating client's caps; afterwards caps = union of the currently attached clients' caps (kept as-is when nobody is attached). `proto.Caps{}` all-false cannot be expressed to `conn` (note 3).
27. **Plain-text game server on a TLS world** ends the session with `tls_error` (note 1).
28. **Closing line text.** `*** Connection closed: <reason>` where reason is a fixed phrase per `endReason` (`closed by remote host`, `connection reset`, `timed out`, `TLS error (<detail>)`, `could not connect (<detail>)`, `disconnected by client`, `squatterd stopped`).
29. **Client library.** `Attach(since)` resets the per-session de-dup floor to `since` (or 0), so a replay after `since=nil` is delivered in full. `Closed` is delivered on a best-effort basis (if the app is not draining `Events()` and the buffer is full it is skipped; `Done()` is always closed). `Dial` without a pinned fingerprint is trust-on-first-use: read `ServerFingerprint()` and store it.
30. **Pairing/devices files are re-read on every `hello`** (no IPC). `pairing.json` read-modify-write across two processes is not locked; the window is a few microseconds and only affects two simultaneous pairings.
31. **Not covered by an automated end-to-end test:** a `since` older than the retained range (`gap` via retention loss) is exercised in `pkg/scrollback` unit tests, not through the wire.
